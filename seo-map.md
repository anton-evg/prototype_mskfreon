# SEO-карта главной страницы ООО «РусХимСоюз»

## Назначение страницы

Коммерческая главная страница поставщика фреона. Страница помогает выбрать марку, увидеть цену, проверить условия доставки и документы, затем отправить заявку на расчет заказа.

## Основной поисковой интент

**Коммерческий с транзакционным продолжением.**

Посетитель сравнивает ассортимент, цену, наличие, доставку и надежность поставщика перед обращением.

## Риск каннибализации

- Главная владеет общим коммерческим запросом **«купить фреон»** и предложением компании в целом.
- `/catalog/` владеет запросами о полном ассортименте и фильтрации.
- Каждая марка R-* получает отдельную товарную страницу и собственный кластер.
- На главной не размещать подробные технические описания марок: они принадлежат товарным страницам.
- Не создавать отдельную страницу `/freon-optom/` без самостоятельного предложения и семантики: она будет конкурировать с главной.

## Требования к исходному HTML

- Один видимый `<h1>`.
- Заголовки блоков использовать как `<h2>`.
- Названия товарных групп и вопросы использовать как `<h3>`.
- Товарные цены, наличие и характеристики должны присутствовать в исходном HTML, а не загружаться только после действия пользователя.
- Переключатели не должны создавать отдельные индексируемые URL с дублирующим содержимым.
- Для главной использовать один канонический адрес через `<link rel="canonical">`.
- Внутренние ссылки должны быть обычными `<a href="...">`.
- Телефон размечать ссылкой `tel:+79035373971`.
- Неподтвержденные изображения должны оставаться placeholder и не получать вводящие в заблуждение `alt`.
- Служебные комментарии, popup, состояния ошибок и таблица усилителей не включаются в индексируемое клиентское содержимое.
- Текстовые данные JSON-LD должны совпадать с видимым содержимым.

## JSON-LD

`{{SITE_URL}}` заменить подтвержденным доменом перед публикацией.

```json

  "url": "{{SITE_URL}}/",
  "inLanguage": "ru-RU"
}
```

### 4. Product

На главной использовать `Product` только для карточек, где одновременно видны и подтверждены название, вариант, цена и наличие. Если наличие большинства позиций не синхронизировано, микроразметку `Product` на главной не публиковать.

Шаблон для товарной страницы или подтвержденной карточки:

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "{{PRODUCT_NAME}}",
  "category": "Фреон (хладагент)",
  "brand": {
    "@type": "Brand",
    "name": "{{BRAND_NAME}}"
  },
  "additionalProperty": [
    {
      "@type": "PropertyValue",
      "name": "Вес газа",
      "value": "{{GAS_WEIGHT}}"
    },
    {
      "@type": "PropertyValue",
      "name": "Вес баллона",
      "value": "{{CYLINDER_WEIGHT}}"
    }
  ],
  "offers": {
    "@type": "Offer",
    "url": "{{PRODUCT_URL}}",
    "priceCurrency": "RUB",
    "price": "{{VISIBLE_CONFIRMED_PRICE}}",
    "availability": "https://schema.org/{{AVAILABILITY}}"
  }
}
```

### Карта полей Product

| Поле Schema.org | Источник | Правило |
|---|---|---|
| `name` | Название и вариант карточки | Должно совпадать с видимым заголовком |
| `category` | Фиксированная категория | «Фреон (хладагент)» |
| `brand.name` | Товарная матрица | Не заполнять для вариантов без бренда |
| `additionalProperty` | Товарная матрица | Показывать только известный вес |
| `offers.url` | URL товарной страницы | Не использовать якорь popup |
| `offers.price` | Видимая цена | Только актуальная подтвержденная цена |
| `offers.availability` | Система наличия | `InStock`, `OutOfStock` или не публиковать |

Для ценовых ступеней не создавать выдуманные скидки. Если на товарной странице одновременно видны разные цены по количеству и способу оплаты, разработчик должен сформировать отдельные подтвержденные `Offer` или отказаться от ценовой разметки до согласования модели данных.

### 5. BreadcrumbList

На главной странице не требуется. Использовать на каталоге, товарных страницах, доставке, документах и контактах после утверждения их URL и названий.

## Что нельзя размечать

- формы в popup;
- скрытые состояния отправки и ошибок;
- cookie-плашку;
- служебную таблицу усилителей конверсии;
- неподтвержденные отзывы с Авито;
- placeholder документов и фотографий;
- наличие по складам без подтвержденного источника;
- социальные ссылки, которые не предоставлены;
- банковские реквизиты как коммерческое предложение.

## Данные, необходимые перед публикацией

- подтвержденный домен;
- канонический URL главной;
- логотип и его публичный URL;
- актуальная система наличия;
- дата обновления цен;
- реальные сканы документов;
- ссылки на публичные профили компании;
- URL будущих внутренних страниц.
